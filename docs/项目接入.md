# 项目接入与复用边界

本仓库提供移动端 CI 的门禁编排、签名运维、交付与恢复机制。应用继续负责自己的源码、Gradle/Xcode/Hvigor
工程和本地检查工具。日常业务代码、业务测试及应用文档只在应用仓库更新，不要求同步修改 CI、共享 Skills 或 Wiki。

当前实际接入使用 Jenkins + Gitee，仓库身份验证和 MR 证明均按 Gitee 契约执行。
[GitHub 接入](GitHub接入.md) 提供独立原生 Android PR 检查入口，严格核对平台事件、fork 与实际提交，
结果由 Actions Checks 提供；不使用 Jenkins/Gitee XML 或生产凭据，工具与 workflow 分阶段固定完整 SHA。
当前 GitHub 不提供发布或自动晋级。公司实例、中性发行包和许可证见 [开源准备](开源准备.md)。

## 唯一项目配置

`projects/<项目ID>.json` 是项目绑定的唯一事实源，随审核过的精确 CI SHA 分发。项目 ID 仅定位该固定目录内的
已审文件，不接受任意配置路径、网页输入或候选应用 MR 覆盖。配置声明应用/CI 仓库与默认分支、信任引用、
平台及适配、Job 的角色和精确全名、供应商逻辑账户与凭据 ID、运行角色、备份范围和门户绑定。
这些 Jenkins/交付字段仅供 Gitee 项目使用；GitHub PR profile 显式声明 SCM/fork 策略并拒绝生产、维护和供应商绑定。
模板字段及确定性生成见[中性模板](模板扩展.md)。

源码里的精确身份校验继续生效：换项目是生成另一组明确绑定，不是取消仓库、Job、权限或门禁白名单。
候选 MR 不得通过删除平台或能力声明逃避受信基线检查；应用构建引用也不能替换签名和发布所需的可信品牌事实。

Controller 使用管理员部署的 `JENKINS_HOME/ci-projects`，目录0700、文件0600，不跟随符号链接；
`JENKINS_CI_PROJECT` 只由管理员部署环境选择已审项目 ID。Controller 不读取候选 MR 工作区。
修改管理员策略仍需部署验收，普通 Job 的 CI SHA 升级不会自动部署 Controller 安全代码或执行维护操作。
首次启动镜像前，管理员须在 Home 卷预创建 `ci-projects`（Jenkins UID所有、0700），再安装审核过的 JSON
（同 UID、0600、单链接普通文件）。官方镜像复制 reference 文件时会用默认权限创建父目录，不能只依赖镜像内
reference 目录的0700；本仓库镜像不内嵌公司项目配置，仍须由管理员显式安装到持久 Home。
已有不符权限、符号链接或来源不明的配置应停止并核验，不在启动脚本中自动放宽或认领。

## 新项目最小接入

1. 增加经审核的项目配置，准确登记仓库、默认分支、所需平台、Job、账户和凭据边界。
2. 使用现有平台适配；工程布局或源码契约不同的项目只补必要的薄适配。应用自己的构建与源码事实不搬入共享运维核心。
3. 渲染并检查 Job/选择器/审批绑定，在受限节点验证仓库、产物身份及签名，不添加任意 shell/hook 配置入口。
4. 核对持久回执、备份资源和接收人，再完成 dry-run 与负向测试；升级前停止全部旧交付进程及队列，离线核对台账后再启动新版，禁止新旧交付工具同时运行。
5. 按固定 SHA 部署并验收新项目。上传、设备注册、通知、市场发布分别需要对应授权，接入检查不会自动执行它们。

## 第二项目可执行示例

[`examples/second-project/`](../examples/second-project/README.md) 使用 `example-mobile`、独立的假 Gitee
仓库、`main` 默认分支、`Example Mobile` Folder/Job、`mobile` 原生 Android 模块和独立逻辑账户。
`project.json` 是公开测试输入，不能作为生产项目配置；验证入口在临时独立双仓库中安装它，不覆盖公司 profile。

从 CI 工具根执行完整本地检查链，先按示例 README 安装 JDK 和受信 Groovy jar：

```bash
export CI_TOOL_ROOT="$PWD"
export PYTHONPATH="$CI_TOOL_ROOT"
export GROOVY_TEST_CLASSPATH=/absolute/path/groovy-all-2.4.21.jar
python3 examples/second-project/validate.py
python3 -m unittest -b tests.jenkins.test_second_project_example
```

验证入口依次准备独立应用/CI 检出、安装审核 fixture、固定提交，调用项目配置校验、应用接口检查、
Job/审批渲染检查、Android `describe` 适配及交付/通知 dry-run。只使用假材料与 mock，默认不执行 SDK 构建、
真实签名、上传、通知或生产恢复；合成 APK 仅验证调用链，不能写为真实 Android 出包。

需要验证该最小应用的真实 Debug 构建时，先按示例准备兼容 AGP 8.9.2 的 Gradle 8.x（至少 8.11.1）、
JDK 17 与 Android SDK 36，再执行：

```bash
python3 examples/second-project/validate.py --build
```

2026-10-13 已在本地 Android SDK 36 / Gradle 8.14 环境执行 `--build` 并通过，生成原生 Debug APK；
这次验证未读取生产凭据、未部署 Jenkins、未调用供应商，Debug 默认密钥不属于生产签名验收。

生产接入仍需把真实 profile 安装到固定受信目录，明确配置应用入口和账户后重新渲染；不能删除 `testOnly`
后直接启用示例账户。部署、项目公钥 recipient、真实 Controller/CPS、权限与审批重启回读按
[运行验收](运行验收.md) 完成。首次真实打包显式设置 `UPLOAD_AND_NOTIFY=false`，不改变生产默认 `true`。

## 交付账户与恢复

项目 ID 与供应商逻辑账户 ID 是稳定身份，凭据只是该账户的认证材料。同一账户密钥轮换不改变逻辑身份；
切换账户必须使用新的受信账户绑定。凭据 ID 由可信 Job 配置绑定，候选应用不能选择其他项目凭据。

上传和通知的回执、锁必须按项目/逻辑账户隔离。已有旧格式状态不能通过换目录、新作用域或清理工作区绕过；
未知、pending、损坏或材料不符时保留证据并阻断重发。原始 upload_key、发布 buildKey 对应、产物摘要、
品牌/平台/版本/包身份及验签仍须核对。收到上传 HTTP 成功响应不代表供应商发布完成。

## 备份的两种范围

Controller 灾备属于 Controller 管理员，恢复包可以包含 Jenkins 全局解密材料及全部配置；其接收人必须明确为
Controller 管理员。项目签名材料备份属于指定项目，不得包含服务器 master.key、全局 secrets 或其他 Folder 配置。
不能通过逐项目替换公钥继续采集整台 Controller。加密快照的接收人也是去重与回读验证的一部分。

部署、备份和恢复消费同一可信运行清单中的服务、卷、回执根及所有者映射。回执不是构建缓存；覆盖不足必须记录
partial，恢复防覆盖、私有权限、原子发布、失败恢复及两份必要回滚包的策略继续有效，不生成备份套备份。

## 验收标准

第二项目 fixture 必须使用不同仓库、默认分支、Folder/Job、单平台布局和逻辑账户，验证实际入口与调用链；
同时保留外来仓库/假门禁、候选降级、路径越界、跨账户回执、旧未知状态、重定向及不同备份接收人的负向测试。
fixture 的供应商与 Docker 操作使用假材料和 mock，不调用真实上传、通知或生产恢复。

本地 fixture 和门禁证明源码契约，不能代替真实工程构建、签名、设备安装和供应商验收。
新增平台、供应商或稳定接口能力才更新负责该能力的仓库；增加普通业务功能不串联其他仓库。

应用 MR 运行应用自己的测试、契约与受影响平台检查，消费固定且已通过 CI 门禁的工具版本；CI 的全部安全、
交付和运维测试由 CI MR 执行。日常业务改动不要求修改或重跑其他仓库的 MR。

当前自动晋级必须绑定该项目的独立 `ci_pr` Job 与精确流水线证明。复用同一个 CI 仓库的新应用可先由管理员
固定通过门禁的 CI 提交；没有独立 `ci_pr` 绑定时不启用自动晋级。共享中央门禁自动晋级尚未实现。

`generate_jenkins_job_templates.py --project=<ID> --check` 可在内存核对新项目模板和审批绑定；
指定 `--output-dir` 时生成/核对该目录的 XML 和审批文件，不覆盖默认项目的审批清单。
远端独立签名导出使用 `signing/export_signing_backup.py --project=<ID> --compose-file=<远端绝对路径>`；
清单与父目录必须分别为管理员所有的0600文件和0700目录，其余必要参数见 `--help`。
`public.sh start` 不隐式重建镜像；更新镜像须先按同一私有清单执行 `stack.sh build`。
