# 鸿蒙环境重建

新 Linux x86_64 主机不需要取得团队私有 Docker 快照。`jenkins/remote/ohos-agent/Dockerfile`
提供公开 JDK 基础与系统运行库；CLT 由获授权管理员从华为官方取得后安装到宿主，再以只读目录挂载。
公开源码包和公开镜像不包含华为 SDK、签名材料、帐号状态，也不会自动接受 SDK 许可。

## 离线安装与独立镜像

在已审源码提交上执行下列命令。`<官方安装包.zip>` 必须是未经重新打包的官方 Linux CLT ZIP；
目的地父目录必须已存在、路径无符号链接，目的地必须不存在。安装失败会回收本次暂存，不覆盖旧 CLT。

```bash
python3 jenkins/remote/ohos-agent/clt.py install \
  '<官方安装包.zip>' '/srv/ci/sdk/harmony-clt-26.0.0.851' --license-reviewed
python3 jenkins/remote/ohos-agent/clt.py check '/srv/ci/sdk/harmony-clt-26.0.0.851'
docker build --platform linux/amd64 \
  -f jenkins/remote/ohos-agent/Dockerfile -t ohos-agent:clt26-jdk21 \
  jenkins/remote/ohos-agent
```

安装器先将输入复制到私有暂存区并核对固定 SHA，再检查 ZIP 完整目录。它拒绝路径越界、重复成员、
特殊文件、特权权限、加密 ZIP、异常压缩格式以及超过固定文件数/单文件/总大小/压缩比例的归档。
相对链接先在归档成员图中解析，接受最长 32 层、总解析步数不超过 250,000 的根内合法链；
拒绝循环、悬空、目录终点和越界，链接也不能作为其他成员的写入父目录。落盘时全部折叠为直接指向普通终点的相对链接。
解压读取校验 CRC；安装后再核对 CLT、SDK、工具版本、许可摘要及签名/打包 JAR，并生成
`ci-install-receipt.json`。该回执记录输入证据，不代替备份核对或授权证明。

镜像固定 JDK 来源，但 apt 使用 Ubuntu 官方签名仓库提供系统修复，系统包没有时间快照锁定，
因此重建保证公开来源和工具契约，不承诺整个镜像逐字节相同。升级 CLT 要同时评审安装包/许可摘要、
实际工具版本和消费端契约，不能通过命令行覆盖摘要或放宽版本来绕过预检。

## 不连接 Jenkins 的运行预检

```bash
docker run --rm --platform linux/amd64 --network none --read-only \
  --cap-drop ALL --security-opt no-new-privileges \
  --tmpfs /tmp:rw,nosuid,nodev,mode=1777 \
  --mount type=bind,src=/srv/ci/sdk/harmony-clt-26.0.0.851,dst=/opt/harmony-clt,readonly \
  --entrypoint python3 ohos-agent:clt26-jdk21 \
  /usr/local/lib/ohos/clt.py check /opt/harmony-clt --runtime
```

运行预检拒绝 root，检查 JDK 21、实际 Node/OHPM/Hvigor、SDK clang 和 `hap-sign-tool.jar -h` 能启动。
它只执行版本/帮助命令，使用私有临时 HOME，不生成证书、不读取业务签名；验收容器的 `--network none` 阻断网络访问。
七个签名/打包工具 JAR 的存在与 ZIP 格式也必须通过（含 HMS 完整签名与 Profile 工具）。Agent 默认 UID/GID 为 `1000:1000`，正式启动在
连接 Jenkins 前执行相同预检；原有私有工作卷、Agent Secret 权限、内存锁及缓存隔离仍由启动入口校验。

官方 CLT 已在 Linux 冷缓存环境完成一次实际应用的无签名 HAP 构建；该结果证明工具链与构建路径可用。
签名验收仍待完成，设备安装和供应商发布也须独立验证；SDK、构建缓存及 HAP 不随公开源码分发。
