# 开源准备与公司实例隔离

原创源码与文档采用 [Apache-2.0](../LICENSE)，归属与第三方边界见 [NOTICE](../NOTICE) 和
[THIRD_PARTY](../THIRD_PARTY.md)，秘密问题报告见 [SECURITY](../SECURITY.md)。通用工具纯源码已公开于 [gycrosskit/mobile-ci](https://github.com/gycrosskit/mobile-ci)；
公开与远端验收结果分别记录，镜像或安装包发行不在本轮范围。

## 本轮验收范围：纯源码发行

本轮只验收原创 CI 源码、文档、中性示例、Dockerfile 和参考 workflow 的中性源码候选包。
Dockerfile 是构建说明，不代表其生成镜像取得分发批准。任何预构建镜像、第三方 JAR/Gem、SDK、
依赖缓存、证书数据、安装包和私有源码/NOTICE 归档均不随此候选包分发。

| 项目 | 本轮归属与状态 |
| --- | --- |
| 原创源码许可、导出清单与秘密检查 | 属于源码准备的技术验收，按实际提交与候选包核对 |
| 115 条未确认组件声明、镜像 NOTICE/对应源码与 SDK 再分发 | 属于镜像/二进制发行阻塞，继续拒绝；不阻断已排除这些材料的纯源码候选包 |
| 官方 CLT 原包与空缓存 HAP 重建 | 已通过隔离运行预检、冷缓存实际应用 HAP 构建与严格签名验签；设备安装及供应商发行未验证 |
| 真实私有安全报告渠道 | GitHub 私有漏洞报告入口已启用；邮箱投递及垃圾分类限制见 [SECURITY](../SECURITY.md) |
| 公开纯源码与 GitHub 验收 | 仓库已公开，远端 Actions 与真实 fork PR 检查通过；结果不等于生产 Jenkins 升级 |
| 镜像与安装包发布 | 不在本轮范围，阻塞及授权分别核对 |

115 条仍是 UNKNOWN，不删除记录、不改为已获许可，也不放宽镜像发行门禁。
如果未来公开包引入任何第三方代码或材料，须核查该实际材料的许可，不能借用本轮源码范围自动放行。

应用源码、品牌事实与公司配置继续留在私有 Gitee；应用沿用 `ci/contract.json`、`ci/brands.json`
和原有 Gradle/Xcode/Hvigor 工程，不新增 YAML、不迁移应用仓库。现有 Jenkins 继续从私有 Gitee
消费应用与固定已审 CI 版本；公开工具仓库的 PR 不自动更新生产 Jenkins，也不读取应用或发布凭据。
GitHub workflow 仅为工具自测或独立无凭据 PR 检查的参考，不是应用必须接入的新入口。

## 私有源与公开源码包

当前私有源保留 `projects/sxmqlive.json` 及公司运维记录，用于已有固定 SHA 的 Jenkins 消费，避免为开源准备
再次迁移生产受信路径。通用 Controller Dockerfile 不复制 `projects/`；管理员在持久 Home 安装真实 profile。
公开示例只含独立假身份与 `testOnly=true`，Python apply 和 Controller 均拒绝将它作为生产配置。

`jenkins/templates/` 使用固定中性字段；Python/Groovy 编译不依赖公司 profile 或旧字符串替换。
原路径的 XML/Pipeline 保留已部署 Controller 兼容快照，并由逐字回归防止漂移，见[模板扩展](模板扩展.md)。
`template-bindings.json` 仅保留历史部署/API兼容，不再作为新版渲染输入。

生成公开候选包：

```bash
python3 jenkins/export_public_source.py --output build/public-source.tar.gz
```

导出只包含 Git 登记的源码和当前未忽略的新增源码：不含 `.git`、任何 `projects/` 生产配置、AGENTS 实例规则、
缓存、运行目录、备份、`.env` 及其变体、签名材料或安装包。只导出 UTF-8 文本源码，
公司 runbook、生产操作和私有验收文档在包内替换为 [通用部署](部署.md) 入口；
私有 Actions 验收链接与镜像原始实例核查 JSON 排除；旧打包、Controller/Wiki API和
模板绑定的固定仓库接线在包内由合成 fixture 中性化，私有源不变，源 Commit 与原/发行摘要保留。Apple CA PEM 不随源码包分发；
管理员通过固定官方来源与 DER 摘要获取，见[许可核查](第三方许可核查.md)。私有生产 bundle 保持原样。
包含 SHA-256 清单，拒绝链接、异常材料、超大文件和疑似私钥，不覆盖已有候选包。导出不安装或默认选择任何项目。
固定配置由源仓库 `projects/<ID>.json` 或管理员私有已审目录提供；优先源配置，
缺失时只接受通过所有者、权限与文件类型核对的管理员配置，不从候选应用或网页输入补齐。
具体唯一接线规则见 [项目接入](项目接入.md)。

公开包保留自足 [第二项目](../examples/second-project/README.md) 与 [GitHub Actions 参考](../examples/github-actions/README.md)，
可离线验证不依赖公司 profile 的模板与 CLI。公共核心通过临时合成 fixture 验证，精确私有兼容用例在受限 CI MR 门禁运行；公开示例证明的范围
与真实工程、签名和供应商验收分开标注。工具源码包含 `.github/workflows` 公共安全自测；
独立应用 PR 门禁的接入、双提交固定与验证限度见[GitHub 接入](GitHub接入.md)。

## 对外发布前

管理员核对源码候选包清单、第三方材料来源与许可、已实际启用的私有安全报告入口，再决定公开发布。
维护者已在 [SECURITY](../SECURITY.md) 登记已启用的 GitHub 私有漏洞报告入口及授权邮箱；私有回执不随源码发行。
不能将源码技术检查通过写成实际公开发布已经就绪。
历史扫描使用固定 Gitleaks，覆盖所有本地 refs 及包括不可达对象的全部 Git 对象；未知命中、缺工具、
浅/部分克隆、预算不足均失败，精确公共代码例外及重跑命令见[许可与扫描记录](第三方许可核查.md)。
发布前先完成源码提交，再重跑扫描并核对实际 HEAD、远端 refs 和发行包；本地扫描不能证明尚未取得的远端对象
或未来更新没有秘密。导出器的私钥特征检查只是补充，不替代该扫描。
发布容器镜像需额外核对实际插件、系统包与 SDK 分发许可；本源码包未携带这些二进制材料。
最新逐项补证见 [镜像许可核查](镜像许可核查.md)：190 条原待确认记录中，55 条取得组件声明、
20 条更正为纯元数据、115 条继续 UNKNOWN。已归档的上游源码和 NOTICE 候选留在私有材料目录，
不随公开源码包复制，也不等于整张镜像取得再分发批准。

鸿蒙已提供固定公开 JDK 基础、离线官方 CLT 安装器和无签名工具预检，见[鸿蒙环境重建](鸿蒙环境重建.md)。
管理员须自行取得对应官方 SDK 及许可；冷缓存 HAP 构建与严格签名验签通过不代表设备安装或供应商发行验收，也不授予 SDK 再分发许可。
