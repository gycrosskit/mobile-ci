# 受管任务生命周期

新增已有能力、启停任务只改管理员审核的项目配置；新增平台、供应商或执行能力才修改 CI 源码。
应用日常业务修改仍只消费固定 CI Commit，不联动 CI、Skills 或 Wiki。

## 配置与边界

`jobs` 的角色和 Pipeline 继续使用固定白名单。可以只声明某个平台的测试任务，不必同时创建正式任务。
每项可增加 `enabled` 布尔值；不接受字符串、任意脚本、URL 或其他 Pipeline。

```json
"jobs": {
  "android_test": {
    "name": "Example Mobile/android-test",
    "pipeline": "jenkins/Jenkinsfile.test",
    "enabled": false
  }
}
```

新生命周期入口消费此启停声明；缺少 `enabled` 时，新建任务禁用，现存任务保留状态。
旧 `sync_jenkins_jobs.py` / `sync_jenkins_admin_jobs.py` 仍保留线上启停与 ACL，沿用其旧 Docker 同步行为。
从配置中省略一项绝不自动删除线上任务。修改任务名也不会自动认领或删除旧名字。

## 预览、应用、验证

以下是管理维护窗口的操作说明，不会在普通应用构建中运行。先安装可信项目配置、固定通过门禁的 CI
Commit，并确认独占管理窗口和队列空闲。Folder 的权限由管理员预先规划；此入口不自动创建 Folder
或授予权限。API 使用 HTTPS，或通过 SSH 隧道连接本机 HTTP；拒绝重定向和 TLS 降级。
Token 存放在本用户所有、0600 的单链接普通文件中，目录和计划文件保持私有，不把 Token 放在参数里。

```bash
export JENKINS_USER='管理员用户名'
export CI_AUTOMATION_COMMIT='已通过门禁的40位CI提交'
python3 jenkins/job_lifecycle.py plan --project=example-mobile \
  --url=https://jenkins.example.invalid --token-file=/private/admin/token \
  --plan=/private/admin/job-plan.json

# 审核 plan 中精确任务、操作、配置摘要后执行；不是日常业务操作。
python3 jenkins/job_lifecycle.py apply --project=example-mobile \
  --url=https://jenkins.example.invalid --token-file=/private/admin/token \
  --plan=/private/admin/job-plan.json --backup-dir=/private/admin/job-backups

python3 jenkins/job_lifecycle.py verify --project=example-mobile \
  --url=https://jenkins.example.invalid --token-file=/private/admin/token \
  --plan=/private/admin/job-plan.json
```

计划不接受外部替换的 XML：应用前按当前可信配置重新生成并比较，随后逐项回读。
XML 可能包含 Jenkins 加密凭据字段，计划及备份只在受限目录保管，不提交公开仓库。
`testOnly` 配置不能部署。认领既有任务须在 `plan` 中显式增加 `--adopt-job=<精确全名>`；
即使名字相同，也必须核对整个受管模板、仓库、固定 Pipeline 和现有权限，不覆盖其他项目。

启用前必须确认所有非 sandbox 脚本的完整审批摘要已存在。标准 ScriptApproval 没有已批准摘要的
REST JSON 接口，此工具只通过固定、无输入插值的 `/scriptText` 只读脚本回读摘要；不批准脚本、
不增加权限、也不暴露任意 Groovy 入口。没有既有管理员权限或缺少精确审批时拒绝启用。
审批部署继续使用已有的受控完整文本审批流程，不自动认领待审批脚本。

## 停用与删除

先将 `enabled` 改为 `false`，执行计划、应用、回读。删除另行将任务从可信配置移除，在 `plan` 中
显式指定 `--delete-job=<精确全名>`，在 `apply` 中用 `--confirm-delete=<同一精确全名>` 确认。
只有本项目已标记受管、已禁用、从未构建且能证明无消费者的任务允许删除。

带构建历史、未知插件类型、SCM 或动态 Pipeline 引用无法证明安全时，删除会被拒绝。
这意味着常规实例中的部分任务只能先停用，再由管理员另行归档和核对消费者；XML 备份不能恢复
丢失的构建历史，不能把此入口称为任意任务的一键删除。必要配置备份只保存本次目标，不备份套备份。

## 失败与并发

REST API 没有原子配置 CAS 或管理员互斥锁。必须独占维护窗口；工具设置 `quietDown`，每步检查队列、
运行状态及配置摘要，避免重启 Controller。未知 HTTP 结果不自动重试；失败保留 `quietDown` 和
`before.json`，管理员先回读、核对部分完成结果，再恢复。工具只在全部回读成功后解除自己设置的
`quietDown`，不会解除此前已有的维护状态。此流程不承诺抵御另一个管理员同时修改，也不自动回滚。

本地测试使用实际 localhost HTTP 服务和合成任务，覆盖新增、启停、认领、删除、幂等及拒绝路径。
它不代替新 Controller 的 CPS、审批持久化、故障恢复和真实产物验收；本轮不改变生产部署。
