# 通用部署与升级

Jenkins 保持正式编排入口。Controller、PR、构建及签名维护承担不同信任角色；GitHub workflow 仅为
无凭据公开检查参考，不替代 Jenkins 管理接口或签名授权。

| 角色 | 运行条件 | 允许的材料 |
| --- | --- | --- |
| Controller | 固定镜像/JDK/插件；管理员部署已审 profile 和安全代码 | 项目与 Job 绑定、受限 Credentials、精确脚本审批 |
| PR | 无生产材料；固定工具链；记录实际应用/CI SHA | 源码、测试、构建缓存 |
| Android/鸿蒙构建 | SDK 预检、预算和并发锁；独立工作区 | 按 Job 临时绑定已审签名材料；交付开启时才绑定渠道凭据 |
| iOS 构建 | macOS/Xcode、固定服务账号、单 Executor | 临时 Keychain/Profile；按渠道绑定凭据 |
| 签名维护 | 管理员触发、独立材料目录、计划和备份优先 | 独立团队 API、0700目录/0600材料；设备/Profile更新与CAS同步 |

## 工具版本与每个 Agent 的配置

[toolchains.lock.json](../toolchains.lock.json) 是受审版本与 OS/architecture 兼容清单。
`toolchains.py` 生成 Docker build args；Mac 安装脚本读取同一版本。Fastlane/Xcode 兼容版本文件、
独立 CLT 安装器和 Docker 默认值必须同时通过 `python3 toolchains.py check`，晋级需评审清单摘要、
官方 artifact 摘要和对应平台兼容性，不能把版本变成 Job 的自由输入。
Controller/Android 基础镜像已固定官方 manifest index digest；完整自定义镜像仍须在管理员主机
构建、验收并登记本机 `sha256:` image ID。基础镜像 digest、完整镜像 ID 和实际运行容器 ID 分别留证。

JDK 锁定 major 21；Android API 36、Build Tools 35.0.0、NDK 25.1.8937393；Xcode 26.3、
Fastlane 2.238.0；Linux amd64 CLT 26.0.0.851 内含 Node 24.14.1、OHPM 26.0.0.630、Hvigor 6.26.8、SDK 26.0.0.105。
Brew/apt 包、Ruby/CocoaPods、Python patch、Fastlane 传递 gem 和 Android platform-tools 未整体冻结。
每个 Agent 的 `expectedVersions` 单独记录 Python 精确版本；iOS 另需 Ruby/CocoaPods 精确版本。
实际只读 preflight 拒绝版本漂移，并保存观察值；这仍不构成整个镜像逐字节可重建承诺。

[deployment_config.py](../deployment_config.py) 验证管理员实例清单并生成 Compose/原生 Mac plist。
清单按 Agent 分配 name/labels、OS/arch、账号、HOME、工作区、两类 Gradle cache、SDK、连接 Secret 引用、
CPU/memory/Executor 和项目 Job 绑定。Controller 零 Executor，Agent 单 Executor；PR、交付和签名维护
的信任边界保持独立。共享 Android SDK 只读挂载，连接 Secret、工作区和运行材料按节点隔离。
清单不允许任意 command/volume/environment 或版本覆盖；Docker target 始终是 Linux，Mac host 与 VM target 分别声明。

```bash
# 无凭据离线预览：示例 image ID、路径与 expectedVersions 都是假数据
python3 toolchains.py check
python3 deployment_config.py plan examples/deployment/linux-with-remote-mac.json --example
python3 deployment_config.py validate examples/deployment/linux.json

# 管理员审核真实项目、镜像和路径以后，才在私有目录生成文件
python3 deployment_config.py validate /absolute/private/deployment.json --private
python3 deployment_config.py render /absolute/private/deployment.json --private --output-dir /absolute/private/stateRoot
```

私有清单目录0700、文件0600；输出目录须等于清单 `stateRoot`，生成入口拒绝覆盖已有文件。
输出包括 `deployment.json`、`nodes.json`、`compose.json` 和每个 native Agent 的独立 plist。
生成结果标记 `applySupported=false`，不创建账号、安装插件、导入 Credentials 或启动服务。
实际获授权后使用同一生成 Compose 与清单执行 `stack.sh check/start`；`start` 使用 `--no-build`。
通用清单模式不自动进入历史 `backup.sh/restore.sh`，先审核其独立资源映射与覆盖范围。

原生 Mac 可配置独立 iOS/CI Agent；Android SDK 节点也可配置并做工具预检，但当前 Android 打包
Pipeline 使用 Linux `flock` 和内存预算契约，清单拒绝将 Android QA/Release Job 绑定到 native Mac。
下一阶段须先完成 Mac 资源互斥/预算适配与签名产物验收，再开放对应 Job 绑定。管理员先按清单安装独立服务账号、锁定工具链和
受审 Remoting jar，再由标准 `launchctl` 安装生成的 `com.mobile-ci.agent.<id>` plist。
旧 `bootstrap-mac-agent.sh --connect-agent` 只安装历史固定 `mac-build` 实例，不是新通用多节点安装入口。
Mac/arm64 的 Android SDK、NDK 必须实际运行 `sdkmanager` 和 NDK clang；缺少可执行的 host 工具或 Rosetta 会失败。
Harmony 当前要求 Linux amd64；Mac 全角色仍需官方 Mac SDK 审核、实际 probe、现有 `/proc` 内存预检的平台适配、
单机资源验证和 HAP/签名验收，不因清单能够填写 Mac 就声明已经跑通。
新 Mac 的 Controller、插件和恢复方案见[新 Mac 迁移](新Mac迁移.md)。

现有应用/CI PR 主 Pipeline 也依赖 Linux 互斥、缓存或固定 Groovy 路径；新清单拒绝将这些主任务绑定到
原生 Mac。Mac CI 节点可独立配置和预检，支持能力不等于所有现有 Job 已迁移；iOS PR 子阶段沿用其
明确的 Mac 标签合同。维护节点必须带已验收 Linux Harmony SDK，不允许生成缺少入口依赖的 maintenance-only 配置。

## 新实例

1. 选择已通过 CI 门禁的完整 Commit；使用 [第二项目示例](../examples/second-project/README.md) 离线确认
   布局、Job、账户及拒绝路径。`testOnly=true` 配置不能安装 Controller 或执行 apply。
2. 管理员另行审核真实项目配置、公司授权、品牌签名及凭据。实例文件留在私有部署目录；源码包和通用
   Controller 镜像不内嵌生产 profile。示例缺项不能自动用旧公司的账户或材料补齐。
3. 用私有 compose 清单明确服务、镜像 ID、节点、卷、材料/回执根及所有者。创建全新 Jenkins Home 时，
   先安装管理员审核的 `ci-projects/<ID>.json`：目录0700、文件0600、Jenkins UID所有、单链接且无符号链接。
   通过部署环境的 `JENKINS_CI_PROJECT` 选择该 ID；不接受候选应用提供文件路径。不要通过启动脚本自动修复来源不明的配置。
4. 独立 Folder 存放本项目 Credentials，并限制实际 Job 权限。按平台安装 SDK；先验证工具版本和预算，
   再渲染固定 SHA 的 XML。模板语法匹配常量是 `jenkins/template-bindings.json`，不是生产 profile。
   新版 Controller 使用固定中性字段表；旧 `template-bindings.json` 仅作历史 API 兼容，
   原路径生产快照继续支持旧 Controller。完整接线及迁移边界见[模板扩展](模板扩展.md)。
5. 先运行无交付验收和负向路径，再按 [运行验收](运行验收.md) 完成真实 Pipeline、CPS、重启审批、公钥
   接收人、签名和回执检查。首次打包设置 `UPLOAD_AND_NOTIFY=false`；上传、通知、设备登记另行按授权执行。

私有源仓库的 Linux/macOS 细节分别见 [Linux runbook](../jenkins/remote/README.md) 与
[macOS runbook](../jenkins/local/README.md)。公开发行包将这两份公司运维记录替换为本通用入口链接。

## 升级和回滚

升级前核对 Controller、节点、队列和旧交付进程。保留本次修改涉及的最小配置/镜像回滚记录和可信清单；
签名变更另做加密材料快照，不把历史备份再次打包。材料、台账和 SDK 缓存分别判断，不能以清理工作区删除未知回执。

普通 CI 工具版本晋级与 Controller 安全代码部署分开验收。更新工具 Commit 不等于加载器、插件、审批和
profile 已部署；Controller 更新时要配套部署 policy、初始化脚本与可信 profile，中性渲染不能取消已有身份约束。
真实 profile 变化需管理员审阅，不能放开候选 MR 对账户、节点、备份或凭据的改写权限。

回滚恢复同一清单中的配置和镜像，保留现有交付回执；先离线核对备份范围/接收人及防覆盖保护，再验证
加载、审批持久化与材料一致。不自动重跑已上传的构建、不重新生成私钥、不重新发送未知结果通知。
