# 运行验收

本文定义接入或升级后的证据清单，不代表每次文档、单元测试或 MR 已完成生产验收。
日常应用业务仍只消费固定 CI；不为了业务改动部署 Controller、重跑签名备份或联动 Skills/Wiki。

## 源码检查与部署检查

源码检查复用 [README Quickstart](../README.md#quickstart先检查再接入) 和
[第二项目验证入口](../examples/second-project/README.md)。Python 测试、普通 Groovy 行为测试、
Declarative 校验及模板 `--check` 分别证明其源码契约；它们不能证明真实 Jenkins CPS 序列化、重启续跑、
线上 ACL 或实际构建。缺失 Groovy 测试运行时产生的跳过项必须记录，不能当作通过。

真实环境复用现有稳定脚本，不另写通用配置解析器：

```bash
# 在受控 Linux 部署主机，消费部署/恢复共用的私有运行清单
bash jenkins/remote/stack.sh verify
bash jenkins/verify-migration.sh remote-linux

# 在实际 mac-build 主机
bash jenkins/local/bootstrap-mac-agent.sh check
bash jenkins/verify-migration.sh mac-agents
```

这些入口只做检查；其项目、清单和节点前提见
[Linux runbook](../jenkins/remote/README.md) 与 [Mac runbook](../jenkins/local/README.md)。
运维、部署、重启、备份和恢复命令仍由各 runbook 唯一维护，不复制另一套操作步骤。

## 锁版本与实际主机预检

先用 `python3 toolchains.py check` 核对受审清单摘要、兼容版本文件、插件直依赖清单和 Docker 默认参数。
此步骤不下载 SDK、不构建镜像、不安装插件；官方基础 image digest 不能替代已建完整镜像与插件二进制验收。
`python3 deployment_config.py plan <实例.json> --private` 只验证/展示受信实例配置；
固定公开示例使用 `--example`，不证明真实 profile 绑定；本机版本用下列 preflight 真实执行。

```bash
# 每个 Agent 独立运行；以下路径与摘要由管理员清单提供
python3 toolchains.py preflight android --sdk-root /absolute/android-sdk --java-bin /absolute/jdk/bin/java --remoting-jar /absolute/agent.jar --remoting-sha256 '替换为已审64位SHA256' --expected-versions /absolute/expected-versions.json
python3 toolchains.py preflight ios --java-bin /absolute/jdk/bin/java --remoting-jar /absolute/agent.jar --remoting-sha256 '替换为已审64位SHA256' --expected-versions /absolute/expected-versions.json
python3 toolchains.py preflight ohos --clt-root /absolute/harmony-clt --java-bin /absolute/jdk/bin/java --remoting-jar /absolute/agent.jar --remoting-sha256 '替换为已审64位SHA256' --expected-versions /absolute/expected-versions.json
```

`expected-versions.json` 来自该 Agent 的受审 `expectedVersions`；只接受精确三段版本，支持 Python、Ruby、CocoaPods。
原生 iOS 在服务账号下运行，`DEVELOPER_DIR` 与该 Agent 清单一致。preflight 验证 JDK、Remoting 摘要及版本、
Android SDK metadata/可执行 host 工具，或 Xcode/首次启动/iPhoneOS SDK/Fastlane/Ruby/CocoaPods，
或 Linux CLT 全树与既有 runtime probe。未支持的 OS/arch、版本漂移、摘要不符、缺少执行工具均失败。
原生 Mac 的 Android 预检只证明 SDK 工具可执行；现 Android 打包 Pipeline 仍按 Linux 内存/互斥契约拒绝 native 绑定。
结果保存 `lockSha256`、实际观察版本和未冻结依赖；`scope=runtime-preflight-only` 不代表真实打包成功。
Python 观察值来自节点实际 PATH 的 `python3 --version`；另以 `probeInterpreter` 记录运行预检 CLI 的
解释器，不能用 CLI 解释器的版本代替 Jenkins Job 将使用的 Python。

多节点还需证明 Controller/node 连接、label 与项目 Job 绑定、实际 UID/HOME、目录所有者、SDK只读、
Secret独占、Executor、CPU/memory 与并发锁生效。Mac Docker VM 资源与原生 Xcode 同时使用宿主资源，
必须在实际新 Mac 测量；清单中的预算不能代替单机峰值检查。完整迁移证据见[新 Mac 迁移](新Mac迁移.md)。

## 每次验收的五组证据

1. **项目与固定输入**：记录项目 ID、受信配置摘要、完整 Job 名、管理员安装来源和权限；分别记录可信
   Pipeline/CI 40 位 SHA、候选预合并 SHA、应用事实 SHA 和实际构建应用 SHA。CI/应用目录无未提交内容，
   构建输出与归档里的 SHA 一致。Gitee 通过评论、Jenkins `building=false/result=SUCCESS` 与实际 Git BuildData
   同时保留；Webhook 源提交、预合并提交不能混用。自动晋级还需证明合并 master tree 与成功门禁 tree 一致，
   受管 Job definition 回读为预期固定 SHA；没有该项目独立可信 `ci_pr` 证据时保持管理员固定版本。
2. **实际 CPS 与隔离**：在真实 Controller 用已部署的固定可信 Pipeline 执行相应门禁或静默构建，
   记录 Controller、插件、JDK 和 Groovy 实际版本及执行结果，验证曾修改的 CPS/权限路径。
   MR 节点不绑定发布材料；伪造仓库、Job、目标分支及缺失权限分别拒绝。普通 Groovy 解释器运行成功不能
   代替此项；CPS 持久化或续跑变更另需在获授权的维护窗口验证 checkpoint 后的重启续跑。
3. **审批持久化**：记录审核过的完整选择器脚本 SHA-512 和部署前 `scriptApproval.xml`/Job 私有备份。
   部署后回读批准哈希、fallback sandbox、固定 Job Build 权限及全局签名撤销结果；不自动批准线上待审批脚本。
   在队列/构建空闲且获授权的维护窗口重启 Controller，再次回读同一审批与 Job definition，确认没有丢失、
   新增越权签名或重复注册。仅启动脚本日志或内存模拟测试不满足持久化验收。
4. **备份接收人与恢复**：记录项目 `signingBackup.scope`、`recipientPath`、`recipientSha256`、公钥所属
   管理员和实际加密报告的接收人摘要。公钥来自受信应用引用，摘要按工具既有规则核对，不能只凭文件名认领。
   项目签名包只含该项目授权 prefixes；Controller 全局灾备只交 Controller 管理员，换项目公钥不能采集
   全局秘密。使用同一私有 Compose 清单验证卷、回执、所有者与完整性；恢复在隔离环境执行并回读，保留
   scope/项目/recipient、归档摘要、回执状态和失败防覆盖证据。没有恢复验证则明确标为“只验证备份生成”。
5. **真实产物与交付**：首次接入设 `UPLOAD_AND_NOTIFY=false`，实际构建并核对类型、品牌、包身份、版本、
   应用/CI SHA、签名和归档。六个 Job 的默认值仍为 `true`，运行前显式核对。设备安装、供应商上传完成与
   通知分别留证；静默构建不能代替这些验收。上传 HTTP 成功不是渠道发布成功；恢复消费原始 artifact/receipt，
   未知、pending 或损坏状态不得通过清目录重发。没有合法正式 Tag 时只记录拒绝路径和测试构建。

验收记录至少包含时间、操作者、项目/Job、上述提交与摘要、已执行结果、跳过或失败项及对应证据位置。
记录里只放摘要、公开身份和受控证据引用，不放密码、私钥、Token、Profile、完整 UDID 或全量备份内容。
GitHub Actions 参考只证明 CLI 在该编排环境的结果，不能写成 GitHub provider 或 Jenkins 生产验收。

公司实例和中性公开发行包的边界由 [开源准备](开源准备.md) 维护；公开示例使用假材料，不触发真实上传、通知或生产恢复。
